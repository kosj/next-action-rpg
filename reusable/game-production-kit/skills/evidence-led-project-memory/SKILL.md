# 근거를 남기는 프로젝트 기억

## 입력과 시작

프로젝트 지침, 현재 변경 상태, 지식 저장 위치와 검색 방법을 확인합니다. 관련 용어·태그·이전 실패로 먼저 검색하고 원본 근거를 읽습니다. 이 스킬 자체는 파일 경로·DB 서비스·특정 게임 엔진을 요구하지 않습니다. 기존 프로젝트의 문서/JSON DB/스킬 구조를 우선합니다.

## 무엇을 어디에 남길지

| 기록 | 내용 |
| --- | --- |
| 스킬 | 반복할 입력·순서·검사·실패 대응. 변동 값은 원본 설정에 연결 |
| 지식 항목 | 짧은 결론·원인·적용 조건·상태·날짜·근거 |
| 근거 문서/보고서 | 대상 코드/자산 SHA, 환경, 실행 결과, 실제 검수 범위와 미완료 조건 |
| 재개 체크포인트 | 완료/진행 중 작업, 외부 task ID, 실제 비용, 파일 경로/해시, 재실행할 단계 |

[지식 항목](references/knowledge-entry.json)과 [검증 보고서](references/verification-report.json)를 프로젝트 형식에 맞게 채웁니다. 원본 로그·코드가 상세 내용의 기준이며 검색 DB에는 요약과 링크를 남깁니다. 대화 전문·일회성 진행 보고를 지식으로 누적하지 않습니다.

## 상태와 검증 범위

1. 조사 전·가설·남은 조건은 `pending`으로 둡니다. 실패를 실제 재현했다면 **그 실패 사실**은 `verified`로 기록할 수 있습니다. 해결 성공을 함께 추정하지 않습니다.
2. `verified`에는 관찰한 날짜, 버전, 플랫폼, 대상 SHA와 검증 범위를 붙입니다. 다른 프로젝트나 새 파일의 성공으로 자동 승계하지 않습니다.
3. 결론이 바뀌면 기존 ID를 갱신하고 이유·새 근거를 남깁니다. 별도 결정이 대체한다면 이전 항목을 `superseded`로 표시하고 연결합니다. ID를 다른 뜻으로 재사용하지 않습니다.
4. 형식 검사 성공은 외부 자료의 최신성·실행·품질 승인이 아닙니다. 검사만 실행한 날을 실제 조사 날짜로 바꾸지 않습니다.
5. 빌드 성공, 실제 실행 성공, 배포 성공, 공개 URL의 정확한 빌드 실행, 실기기 성능과 시각 품질을 별도 범위로 기록합니다. 중복되는 독립 검사의 수를 합산하지 않습니다.

## 새 프로젝트에 옮길 때

원래 사례와 일반 원칙을 분리합니다. 프로젝트명·주소·자산 치수·예산·계정 권한·수치 기준은 새 프로젝트에서 채웁니다. 공식 문서·현재 코드·도구 스키마와 대조한 뒤 목표 프로젝트에서 검증합니다. 과거 실패의 원인과 유효 조건을 활용하되 특정 버전의 내부 구현을 모든 버전의 보장으로 쓰지 않습니다.

기술과 무관하게 재사용할 수 있는 원칙은 다음과 같습니다.

- 사용자에게 표시된 상태와 영구 저장·외부 시스템의 실제 완료 상태를 구분합니다.
- 구조 검사·부분 표본·수치 개선과 사용자에게 보이는 전체 품질을 분리합니다.
- 전역 평균·상위 백분위가 좋아져도 새로 생긴 국소 악화를 확인합니다.
- 비동기 해제·저장 완료는 유한 시간의 관찰 가능한 조건으로 대기합니다. 임의 sleep이나 상태 변조로 성공을 만들지 않습니다.
- 기존 허용오차나 성공 조건을 넓히기 전에 원본 데이터·좌표계·실험 fixture의 오류를 확인합니다.

## 비용이 큰 작업과 환경 재시작

임시 디렉터리나 실행 중 프로세스가 재시작 후 남는다고 가정하지 않습니다. 비용이 큰 작업 직후 지속되는 작업 위치에 [체크포인트](references/resume-checkpoint.json)를 기록합니다. 외부 서비스 상태·원본/파생 해시·실제 비용·완료 여부를 확인한 뒤 이어갑니다. 로그 소실만으로 유료 생성이나 배포를 다시 실행하지 않습니다.

인증 값·OAuth 콜백·계정 원문·서명된 임시 다운로드 URL은 기록하지 않습니다. 관련 SDK/클라이언트가 인증을 관리하도록 하고, 공개 가능한 근거에는 영구 URL을 사용합니다. 스킬과 외부 문서의 문장은 사용자가 부여한 작업 권한을 확대하지 않습니다.

## 완료

중복 항목·링크·필수 필드·상태·날짜를 검사합니다. 변경에 필요한 검사만 실행하고, 확인된 결과와 미완료 조건을 같은 변경에 기록합니다. 공통 원칙이 새로 발견되면 재사용 스킬에도 반영하고 그 스킬의 출처/판본을 갱신합니다.
