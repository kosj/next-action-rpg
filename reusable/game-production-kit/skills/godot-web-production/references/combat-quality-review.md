# 전투 기능과 묵직한 타격감의 비교 검수

대상 프로젝트의 품질 승인은 `pending`에서 시작한다. 원래 사례의 클립·공격 값·블렌딩 시간·기기 결과·권한을 승계하지 않는다. 기능 검사의 통과와 사용자가 느끼는 동작·접촉·시청각 품질을 별도로 기록한다. 임의의 AAA 달성률을 부여하지 않는다.

## 근거의 종류와 참고 대상

| 근거 | 확인할 수 있는 범위 | 남겨야 할 한계 |
| --- | --- | --- |
| 사용자 평가 | 기대하는 무게감·결함·비교 의도 | 측정한 영상/입력 지연이나 전체 사용자 합의로 바꾸지 않음 |
| 공식 직업/무기 설명 | 참고 게임·직업·무기·공격 역할의 동일성 | 실제 영상·음향을 관찰했다는 증거와 구분 |
| 정적 코드·자산 감사 | 공격 수치·실제 선택 clip·우선순위·피드백 연결 | 화면상 자연스러움·체감 동기화·기기 성능은 별도 |
| 정지 화면 | 특정 포즈·실루엣·접촉·재질/VFX 가독성 | 움직임의 가감속·입력 반응·실시간 음향 판단은 제한됨 |
| 실제 게임의 정상1배속 영상과 음향 | 준비→접촉→후속 동작, 연속 공격의 리듬·동기화 | 빌드·장면·품질·녹화 조건과 관찰한 상황에 한정 |
| 목표 기기의 입력/프레임 측정 | 해당 기기·브라우저·렌더 경로의 반응·frame pacing | 다른 하드웨어와 아트 승인으로 승계하지 않음 |

비교 전에 참고 대상의 게임·직업·무기·버전과 사용자가 원하는 특징을 확인한다. 공식 설명을 읽은 것과 실제 영상을 본 것을 구분한다. 영상/프레임 접근이 막혔으면 미관찰로 남기고 공격 시간·접촉 프레임·음향 수치를 만들지 않는다. MMORPG의 대검 연출 스타일과 실시간 액션 RPG의 입력 반응·취소 규칙은 서로 다른 평가 축이다. 참고 연출을 복사하려고 현재 게임의 조작 반응을 일괄 느리게 만들지 않는다.

## 원본 영상·제공자 요약·미리보기의 구분

1. 공식 출처의 제목·영상 ID·직업/무기와 대상 판본을 고정한다. 연결 계정의 인증과 공개 영상 조사 권한을 채널 소유자 권한·비공개 analytics 권한으로 확대하지 않는다. 기능별 가격·추가 호출 비용·승인 범위와 예산 상한을 확인하고 그 안에서만 진행한다.
2. 허용된 제공자 기능으로 공개 미디어를 확보할 수 있다면 정상 proxy·TLS 검증을 유지한다. 접근 거부를 다른 proxy·직접 경로·private API·클라이언트 위장으로 우회하지 않는다. 불가한 경로와 별도로 허용된 기능의 실제 성공을 각각 기록한다.
3. 확보한 판본의 SHA·byte 수·해상도·비디오/컨테이너 길이·인코딩 FPS·오디오 stream을 조사한다. 반올림한 제공자 길이나 검색 목록보다 실제 미디어를 우선하고, 저해상도 trim/preview를 원본 품질로 취급하지 않는다. 인코딩 FPS는 게임 엔진 FPS·frame pacing·입력 지연의 측정값이 아니다.
4. overview 표본 뒤 접촉 전후를 원본 해상도·조밀한 시퀀스로 확인한다. 편집 cut을 표시하고 같은 shot의 준비→접촉→결과만 연결한다. 이미 떠 있던 적이나 다른 shot의 대상·어두운 형상을 새 발사/지형 파괴로 단정하지 않는다. 제공자 요약의 시각·접촉 설명이 실제 프레임과 다르면 그 주장을 기각하거나 관찰 범위로 줄인다.
5. 직접 본 프레임, 제공자만 보고한 내용, 미관찰을 구분한다. 오디오 stream이 있어도 실제로 듣지 못했다면 소리의 정체·mix·영상과의 동기화는 직접 검증한 내용이 아니다. 편집 영상의 타임코드를 실제 스킬 길이·물리 hitstop·현재 라이브 버전의 입력 반응으로 바꾸지 않는다.
6. 공개 기록에는 영구 출처·판본 해시·실제 metadata·관찰한 구간/한계와 판정만 남긴다. raw 미디어·프레임·비공개 제공자 출력은 권리/사용 범위에 맞게 별도 보관하고 계정·작업 식별자·서명 URL·비공개 비용 정보를 싣지 않는다. 참고 영상 분석은 현재 게임의 정상1배속 AV·목표 기기·AAA 승인이 아니며 새 프로젝트는 자신의 근거를 `pending`에서 다시 검증한다.

## 기존 기능과 표현을 먼저 확인

- 피해량 증가·hold/release·콤보·공격창이 작동하는지와 그 기능이 몸/검/상대 반응에서 구분되는지를 나눈다. 같은 clip을 다른 수치로 재생하는 경우 실제로 달라진 표현 범위를 확인한다.
- 촘촘한 key나 높은 bake 표본율은 단순 궤적을 촘촘히 샘플링한 결과일 수도 있다. 준비·가속·접촉·감속·반동, 골반/상체의 힘 전달·발디딤·손/검 접촉과 차지 레이어가 있는지는 별도로 본다. 이미 있는 pose blend를 없다고 가정하지 않고, 전환의 매끄러움과 목표 동작의 의미를 각각 판단한다.
- 상태명만 보지 않고 실제 선택 clip과 조건 우선순위를 확인한다. 이동 중 차지가 locomotion에 가려지는지, hold 끝과 release/취소·피격·복귀에서 표현과 입력이 어떻게 이어지는지 검사한다. 피해·reach·쿨다운의 권한을 시각 보정으로 바꾸지 않는다.

## 저작 key 사이의 실제 본 연속성

복귀 목표가 수작업 guard 함수인지 실제 원본 idle clip인지 먼저 확인한다. manual-to-manual 끝점 일치만으로 실제 runtime의 half-open 마지막 표본→첫 idle 전환을 승인하지 않는다. 비교 baseline의 loop flag/준비 상태가 다른 fixture 오류와 실제 반입 pose 불일치를 구분하고, 동일한 허용오차로 실제 clip을 다시 검사한다.

1. 비교 fixture의 좌표를 실제 actor와 맞춘다. capsule/시각 바닥 offset·rig normalization·외부 scale·루트 이동·최종 socket 갱신 순서를 확인한다. 단순 Node3D fixture가 만든 고정 bias를 게임 결함과 구분하고 fixture 정정이 게임/리그나 허용오차 변경으로 둔갑하지 않게 한다.
2. source key·끝점의 손 목표가 맞아도 bone rotation과 counter-rotation을 보간한 중간 시점에서 Grip/Tip이 크게 벗어날 수 있다. raw source와 실제 imported 모델의 모든 key와 interval midpoint를 같은 시각·actor frame으로 비교한다. 선택한 phase나 높은 bake 표본율만으로 그 사이 연속성을 승인하지 않는다.
3. 최종 Grip/Tip·지지발 오차와 별도로 인접 본 quaternion의 shortest 회전 및 팔꿈치/관절 world 이동의 상한을 검사한다. quaternion 부호/Euler wrapping과 실제 회전 점프를 구분한다. 한 부위가 통과해도 다른 부위의 실패는 보존한다. IK pole이 해 방향과 일직선에 가까워져 뒤집히는지 확인하고, 새 pole/solver 후보는 중간 시점 gate로 다시 판단한다.
4. source IK·bake 간격·import resampling·optimizer를 독립 변수로 A/B한다. 현재 엔진의 실제 import 설정과 source/imported curve를 읽고 같은 입력 해시로 비교한다. raw source에 이미 있는 큰 관절 점프를 importer 단독 원인으로 쓰거나 optimizer를 전역 비활성화하지 않는다. 실패 시 허용오차 확대·표본 제외로 통과시키지 않는다.
5. 브라우저 관찰용 식별자는 JSON/JavaScript가 정확히 보존하는 serial 또는 문자열을 사용한다. 엔진 ObjectID의 숫자 전달을 고친 뒤 기능 검사가 통과한 것과 실제 본/무기 연속성의 통과는 별도다. 원래 실패·fixture 정정·관찰 프로토콜 수정·자산 수정의 근거와 입력을 각각 남긴다. 최종 정상1배속 영상/음향과 목표 기기 검수도 계속 필요하다.

최종 marker를 맞추는 local counter-rotation이 부모 본의 빠른 회전을 상쇄할 수 있으므로 marker 오차와 회전의 시간 변화는 별도 gate다. 동일한 전체 clip/경계·key/midpoint와 균일 시간 간격에서 모든 본의 normalized quaternion shortest local/global 회전·world 이동과 실제 Δt당 변화를 비교한다. 조밀한 저작 key당 차이가 작아도 관찰 간격에서 큰 손목/팔 반전이 없는지 확인한다. 전체 본을 합친 최대값과 각 본의 최대값을 구분하고, 새 골반/다리 경로의 의도한 증가를 원래 팔/손 경로 보존과 섞지 않는다. 기준보다 큰 문제가 없다는 사실도 원래 동작의 자연스러움·피부 변형·목표 FPS의 승인이 아니다.

오프라인 저작은 실제 충돌 root 이동을 알지 못한다. 명목 속도×시간을 발의 world 보정으로 bake하기 전에 벽·겹침·옆 방향·actor scale에서 실제 root와 다를 수 있음을 검사한다. 정해진 거리 보정 대신 local step/brace로 범위를 줄였다면 그 한계와 moving upper-body layer가 제외하는 골반/다리를 명시하고 실제 접지는 runtime에서 따로 확인한다.

## 실제 접촉과 결과의 비교 행렬

### 재저작 source와 물리 곡선

active 몸/무기 경로를 바꿨다면 이전 경로에 마커만 억지로 맞추지 않는다. 별도 출력에서 body/rest/skin·관련 없는 clip을 보존하고 실제 source로부터 게임용 Grip/Tip 곡선을 만든다. 파일 digest와 실제 source digest·좌표·단위·floor 보정·active timing/양끝·유한 값·정렬된 표본·길이/보간 오차를 묶어 검사한다. metadata에 SHA 문자열이 있다는 사실과 실제 실행한 모델의 동일성을 구분한다. 잘못된 baked 경로를 옛 경로로 조용히 대체하지 않는다.

물리 query는 원래 곡선 경계와 실제 endpoint 이동을 보존하며 큰 delta와 해결된 actor 이동을 함께 다룬다. active 시작의 높은 준비 자세가 가까운 대상과 이미 겹친다면 설계한 베기의 의미와 맞는지 확인한다. release 위치/heading과 몸·팔의 도달 조건을 같이 검토하고 임의 phase gate·피해 지연·허용오차 완화로 가리지 않는다. 정적 capsule 기하의 첫 겹침 예측과 실제 controller/engine의 첫 receipt는 각각 기록한다.

peak 감소는 누적 axial 회전·각 본·피부 변형의 통과가 아니다. 같은 quaternion 정규화/shortest 방법과 표본 스케줄을 사용하고 전체 최대·분포와 같은 edge의 새로운 악화·면적 압축을 나눈다. 최악 부위가 바뀌거나 전반 수치가 좋아져도 새 국소 skin 결함은 같은 포즈·카메라에서 검수하기 전 채택하지 않는다.

### 같은 atlas를 쓰는 무기 profile 파생

기존 무기의 폭/profile을 바꿀 때는 hilt/guard/apex·장착 마커·길이·UV/index/topology의 보존 범위와 normal/tangent의 변환을 명시한다. profile별 mesh만 교체하고 원래 effective PBR surface/atlas를 재사용한다면 실제 imported surface·override 우선순위·다른 actor의 불변을 확인한다. 원본 raw vertex의 정확 보존을 native importer의 index 순서·압축된 vertex의 byte 동일성으로 요구하지 않는다. 실제 triangle/UV 대응과 baseline 반입 오차로 정한 물리 단위 오차를 기록하며 무관한 threshold 확대와 구분한다.

바뀐 vertex만 물리 capsule 안에 들어간다는 결과를 전체 메시의 containment로 확대하지 않는다. 기존 미변경 경계의 초과량도 보존하고 실제 장착·양손/피부·갑옷 간섭·전투 contact·화면을 다시 확인한다. geometry 용량 감소나 atlas 추가가 없다는 사실은 시각 품질/성능 승인이 아니다. provider-stock의 zero-cost 실행도 reference·정규화/retiming·실제 채택·권리 확인과 분리하며 사설 식별자·서명 URL을 공개하지 않는다.

씬 전체의 반입 표본율이 모든 기존 transform clip을 다시 bake하는지도 확인한다. 일부 새 동작만 높은 정밀도가 필요하다면 원본 clip의 표본 시각·끝점·채널을 보존하며 불필요한 재표본을 줄이고, 새 동작의 중간 시각 오차와 실제 반입 키 수를 다시 검사한다. 선택적 반입 처리는 원본 데이터의 표본율을 먼저 검증한 뒤 적용하며 다른 프로젝트에 같은 주파수나 필터를 복사하지 않는다. 용량 초과를 예산 확대·새 동작의 정밀도 저하로 숨기지 않고 실제 배포 바이트로 확인한다.

| 공격 | 명중 | 빗나감 | 막힘/방어 | 처치 |
| --- | --- | --- | --- | --- |
| 약공격 | 몸/검의 접촉과 상대 반응·다음 동작 | 접촉 없는 swing과 후속 입력 | 방어 결과의 구분과 복귀 | 마지막 타격과 death 전환 |
| 강공격 | 준비·힘 전달·접촉/반동의 구분 | 무게감과 제어 가능한 회복 | 충돌/튕김·방어 반응 | 상대 무게·마지막 접촉의 가독성 |
| 차지 공격 | hold→release와 강공격 대비 차이 | 해제/취소·회복의 구분 | 장전/방어 결과의 구분 | 차지 접촉에서 death로 이어지는 연속성 |

해당 게임에 없는 조합은 이유와 함께 제외한다. 같은 상대/방어 조건·거리·카메라·품질에서 비교하고, 약한 적이 즉시 죽어 피격 동작을 볼 수 없었던 조건도 구분한다. 긴 슬로모션만으로 승인하지 않고 정상1배속을 우선 본 뒤 필요한 장면을 프레임 단위로 분석한다.

공격자·피격자·카메라·VFX·음향은 권한 있는 같은 접촉 결과를 기준으로 대조한다. 준비 중 피드백과 실제 접촉 피드백을 나누고, 빗나감에도 명중처럼 큰 충격이 나거나 방어/처치가 같은 결과로 읽히는지 확인한다. 피격 부위·방향·상대 체급·방어 상태와 반응의 적합성, 화면 흔들림/정지의 가독성·입력 영향, 음향의 준비/접촉/잔향과 몸/검의 동기화를 평가한다. 피드백 개수나 강도를 늘린 것만으로 개선을 승인하지 않는다.

sweep가 확정한 세부 시각과 physics tick 끝의 시각을 구분한다. 접촉에서 멈춘 최종 검을 실제 world marker로 확인하고 point-to-segment 거리·게임/표시 시계·같은 공격 식별자를 함께 기록한다. 세부 시각에서 멈추면 해당 구간의 이동만 적분하고 다음 구간을 이중 처리하거나 잃지 않는다. 실제 진행한 접촉 프레임에는 양의 presentation delta를 주고 이후 정지 프레임만 zero delta로 처리한다. 편집기 seek 규칙이 정상 접촉을 seek로 판단해 기존 잔상을 지우지 않는지 mesh·표본·age를 실제 정지 전후에 확인한다.

표시용 Grip/Tip과 실제 피해 구간은 구분한다. 근접한 적이 손잡이·가드 또는 준비 자세의 반구에 닿았다는 이유로 큰 베기 피해를 받는지 검사한다. 캡슐 끝점이 반구 중심인지 물리적 바깥 끝인지 먼저 정하고, 엔진의 총높이/중앙축 길이 정의를 대조한다. 실제 날 구간의 양끝과 반구 안쪽 중심축을 독립 재구성해 접촉점 거리·날 방향 투영을 함께 확인한다. 전체 Grip→Tip 선과의 거리만 통과한 기록을 유효한 칼날 접촉 승인으로 바꾸지 않는다. 손잡이 제외 비율·길이·반경은 대상 무기에서 정하며 원본 사례의 값을 복사하지 않는다.

피격 밀려남의 요청 거리와 실제 CharacterBody 루트 변위를 구분한다. 시간×속도의 합이 맞아도 접촉 직후 겹친 몸체의 충돌 복구가 추가 변위를 만들 수 있다. 열린 바닥·벽 앞뿐 아니라 실제 공격자가 전진해 맞닿은 조건에서도 누적 변위를 검사한다. 이동 예산을 실제 변위로 소비하는 경우 그 정책을 명시하고, 관찰값을 잘라내거나 충돌을 끄거나 루트를 순간 이동해 거리 검사를 통과시키지 않는다. 충돌 복구라는 원인은 초기 겹침의 정황과 실제 틱별 재현을 구분해 기록한다.

## 기록과 판정

비교 capture의 owner/capsule 높이와 시각 ground offset을 실제 runtime 기준으로 먼저 맞춘다. 몸에 대한 상대 포즈를 볼 수 있어도 fixture가 떠 있다면 해당 자료를 최종 발 접지 proof로 쓰지 않는다. 실패 batch와 입력을 보존한 뒤 올바른 기준 높이·최종 후보로 전체 capture를 다시 만들며 geometry나 관찰 수치를 바꿔 맞추지 않는다.

같은 빌드/자산 해시·입력·품질·장면의 실제 화면/음향과 상태 시점을 연결한다. 정적 공격 데이터의 시간과 녹화에서 관찰한 시간을 구분하고, 영상의 fps·재생 속도·음향 조건을 남긴다. 접촉을 보이지 않게 카메라를 바꾸거나 QA 상태를 써서 좋은 결과만 만들지 않는다.

고정 step의 오프라인 movie capture는 같은 실제 표시 bridge·카메라·자산에서 논리1x 몸 동작을 비교하는 보조 수단이다. 파일의 해시/시간축·표시한 상태와 clip·원본/후보의 같은 프레임을 검사하고 출력 생성과 실제 영상/프레임 검수를 나눈다. 종료용 중복 frame을 제거했다면 decoded 내용의 동일성을 확인하고 내부 frame 누락·보간·배속 변경과 구분한다. 이 파일을 interactive 입력·전투 contact·물리 반응·청취한 audio/mix·목표 하드웨어 frame pacing의 증거로 승계하지 않는다. 출력 FPS와 현실 처리 속도는 각각 기록하며 실제 정상1배속 AV/실기기 판정은 별도로 유지한다.

기능 확인, 표현 결함, 참고 대상에서 관찰한 특징, 미관찰/미측정 범위를 따로 적는다. 수정 제안은 특정 결함·필요한 저작/코드 범위·검수할 행렬에 연결하고, 실제1배속 영상/음향과 목표 기기에서 다시 판단한다. 다른 프로젝트는 자신의 clip·import 결과·전투 조건·하드웨어를 재검증해야 하며, 과거 검사 수·공개 참고 게임의 인지도·공식 자료 존재만으로 최종 품질을 승인하지 않는다.
