# 설계와 구현 상태

## 제작 방향

독자적인 판타지 세계관의 싱글플레이 액션 RPG. 주인공은 성인 여성 룬 검사 리라, 첫 챕터의 무대는 몰락한 성역입니다. AAA급은 장기 품질 목표이며 첫 제작 목표는 30~60분 챕터입니다. 무료 도구·보유 크레딧·직접 제작을 우선합니다.

첫 챕터: 거점 → 순례자의 뜰 → 침묵의 회랑 → 깨진 서약 → 달빛의 정원 → 잿빛 제단 → 마지막 문 → 타락한 성역. 일반 전투 6곳과 보스전 1곳, 체크포인트 3곳, NPC 2명, 기록 3개(선택 탐험 길 2곳)를 포함합니다.

## 현재 구현

- 코드가 제어하는 이동·달리기·대시 회피, 카메라 충돌, 적 고정·다른 대상 선택.
- 약공격 3연타, 강공격과 차지, 룬 스킬 3종, 패링, 회복약, 피격 경직·짧은 무적.
- 물리 틱 기반 공격 준비·활성·회복·취소 구간, 입력 예약, 적당 한 번의 타격 등록, 경로를 따라 표본화하는 구체 스윕.
- 근접·방패·원거리 적, 강화 정예, 동시에 공격하는 적 제한, 일반 적 체력 표시.
- 아스테르 보스: 체력 50%에서 2단계로 전환, 공격 준비 시간 단축, 패링 불가 원형 충격파.
- 전투 구역 봉쇄·해제, 처치 보상, 룬 강화 3종(각 3단계), 도입·NPC·기록·결말 텍스트.
- 로컬 버전 저장, 임시 파일을 통한 교체, 백업 복구, 구조와 값 범위 검증.
- 한국어 HUD·타이틀·일시정지·조작 안내·음량·화면 흔들림·성능 모드.

## 코드 경계

`AttackData`는 피해량·자세 피해·준비/활성/회복 시간·거리·각도·전진량·패링 가능 여부를 정의하는 Resource입니다. 공격 중에는 공유 Resource를 변경하지 않습니다.

`CombatStrike`는 공격 인스턴스마다 시간과 대상별 타격 기록을 소유합니다. 물리 공간에 구체를 연속 표본화하여 이전·현재 검 위치 사이를 검사하고, 공통 `receive_hit(amount, poise, origin, parryable)`로 피해를 전달합니다. 벽과 대상 고정은 별도 물리 질의로 처리합니다.

`RunePlayer`와 `RuneEnemy`는 이동·피격 상태를 소유하고, 전투 성공과 사망을 신호로 전달합니다. `ActorVisual`은 Blender에서 내보낸 관절 피벗을 움직이는 임시 애니메이션 계층입니다. 최종 스켈레톤과 AnimationTree로 교체할 때 전투 시간·판정은 이 표현 계층으로 옮기지 않습니다.

`Sanctuary`는 충돌이 있는 방·길·문과 시각 자산을 생성합니다. `game.gd`는 순차 전투·상호작용·보상·체크포인트를 관리합니다. `RuneHUD`는 일시정지 중에도 UI를 처리하고, 전투 도중에는 진행을 대신 결정하지 않습니다.

저장 v1 필드는 `version`, `completed`, `checkpoint`, `shards`, `upgrades`, `lore`, `settings`와 선택 필드 `journey_started`입니다. 설정만 저장한 파일은 이어하기 슬롯을 만들지 않으며, 이 필드가 없는 기존 v1 파일은 여정이 시작된 것으로 읽습니다. 알 수 없는 버전은 적용하지 않고 백업을 확인합니다. 런타임 인스턴스나 Resource 객체를 저장하지 않습니다.

## 아직 완료하지 않은 품질 작업

- VARCO 최종 모델, 캐릭터 얼굴·손·머리카락의 완성 아트, 실제 스켈레톤·25~35개 모션과 AnimationTree.
- 서로 구분되는 4개 환경의 완성 아트, 세밀한 세트 드레싱, 완성 음향·음악·음성.
- Windows용 고해상도 자산과 별도 LOD 묶음. 현재는 같은 저용량 모델을 공유하고 해상도·그림자와 렌더러를 구분합니다.
- 30~60분 플레이 시간과 난이도 조정, 신규 테스터 3명 이상의 플레이테스트.
- RTX 3060 기준 성능 측정, 실제 Windows와 Edge에서의 조작·렌더링 검증.

현재 코드는 첫 챕터의 플레이 루프를 검증하는 기반입니다. 이 항목들이 완료되기 전에는 최종 챕터나 AAA급 결과물로 표기하지 않습니다.
