# Blender · VARCO 제작 가이드

2026-10-30에 공식 자료와 공개 Godot 스킬을 대조했습니다. 상세 근거·현재 GLB 실측·버전 변경 조건은 [아트 파이프라인 재검증](ART_REVIEW.md)에 기록합니다.

## 제작 방향

현재 단순 도형 생성기는 게임 기능 검증용 블록아웃입니다. Blender의 제작 품질 한계나 최종 아트 방식으로 취급하지 않습니다. **VARCO의 이미지/3D 생성·재질·리깅·모션 후보 → Blender의 조형·토폴로지·UV·웨이트·재질 후처리 → Godot의 애니메이션·조명·VFX·화면 검수**를 기본 제작 흐름으로 사용합니다. 주인공도 생성 후보에 포함하며 범용 소품으로 사용 범위를 제한하지 않습니다.

VARCO에는 [공식 MCP 서버와 Codex 연결 경로](VARCO_MCP.md)가 있습니다. 연결·인증·도구 발견·실제 호출 성공을 각각 확인합니다. MCP 연결은 제작 자동화의 조건이며 최종 품질은 생성 결과와 후처리·장면 통합을 검수해 판단합니다.

## 현재 자산

Blender 4.3.2의 Python API로 직접 제작한 주인공·수호병·보스·기록관의 `.blend` 원본과 `.glb`를 포함합니다. 영리 사용 조건이 불명확한 모델이나 외부 모션은 사용하지 않았습니다. 효과음과 배경 패드는 Python으로 합성한 임시 소리입니다.

```bash
blender -b --python art_source/generate_assets.py
python art_source/generate_audio.py
```

첫 명령은 4개의 Blender 원본과 GLB를 다시 생성하며 기존 파일을 덮어씁니다. 수작업으로 다듬은 원본은 별도 이름으로 보관한 뒤 실행합니다. Git LFS는 `.blend`에 적용하고, 작은 런타임 GLB는 일반 Git으로 관리합니다.

## 아트 가이드

- 리라: 성인 여성, 현실적인 인체 비례, 은회색 머리, 흑철 갑옷·청록 천·오래된 금색 장식, 청록 룬검. 얼굴과 실루엣은 독자 디자인으로 제작합니다.
- 수호병: 손상된 청동 갑옷, 잿빛 천, 주황빛 균열. 근접·방패·원거리 역할은 색 외에도 무기와 실루엣으로 구분합니다.
- 아스테르: 인간보다 큰 파수꾼, 왕관 같은 관 장식과 긴 검. 2단계에서 룬 균열이 밝아집니다.
- 환경: 순례자 구역의 밝은 돌, 회랑의 차가운 석재, 정원의 이끼, 제단의 그을음. 멀리 보이는 폐허와 발밑의 룬이 길을 안내합니다.

## VARCO에서 최종 자산으로

1. 정면·측면·후면의 비례, 실루엣·얼굴·의상·무기·재질을 정의하고 모델별 지시문과 참조 이미지를 작성합니다.
2. [VARCO MCP](VARCO_MCP.md)로 선택한 Flow를 확인하고 이미지·3D·재질·리그·모션 후보를 생성합니다. 주인공·대표 적·환경 모두 후보에 포함합니다. 현재 세션에서 인증과 실제 생성은 아직 검증하지 않았습니다.
3. GLB로 내려받아 Blender에 반입합니다. 로컬 Blender 환경이라면 [VARCO Blender Bridge](https://3d.varco.ai/docs/blog/2026-03-19-varco-3d-bridge-for-blender)를 사용할 수 있습니다. 클라우드 작업 공간과 로컬 브라우저 사이에 이 연결이 자동으로 있다고 가정하지 않습니다.
4. 비정상 면·법선·교차를 정리하고, 얼굴·손·관절의 토폴로지, UV와 재질, 리깅·웨이트를 보정합니다.
5. 공통 스켈레톤에 이동·피격·회피를 먼저 연결한 뒤, 핵심 콤보의 시작·중간·끝 자세와 발 접지를 제작합니다. 무료 모션을 사용할 때에도 출처와 재배포 조건을 기록합니다.
6. Blender에서 GLB를 명시적으로 내보내 Godot에 반입하고, 게임 씬에서 재질과 충돌·손의 무기 위치를 검수합니다. 원본 `.blend`를 런타임 프로젝트에 넣지 않습니다.

현재 `ActorVisual`은 `Torso`, `Head`, `ArmL/R`, `ElbowL/R`, `LegL/R`, `KneeL/R`, `HandL/R` 피벗을 사용합니다. 최종 리그는 이 임시 계약에 억지로 맞추기보다 ActorVisual의 표현 구현을 교체합니다.

현재 네 GLB에는 `skins`와 `animations`가 없습니다. 최종 캐릭터는 별도의 `Skeleton3D`·스킨 웨이트·`AnimationLibrary`를 반입한 후 `AnimationPlayer`의 클립을 `AnimationTree`에서 재생·블렌딩하는 방식으로 전환합니다. 임시 피벗을 곧바로 합치면 현재 코드 애니메이션이 깨지므로, 메시 통합은 최종 리깅 이후 수행합니다. 이동·공격 시간과 판정은 게임 코드가 계속 소유합니다.

## VARCO 생성물 기록

[2026-10-12 공식 변경](https://3d.varco.ai/docs/release-notes/2026-10-12-choose-a-license-when-you-generate)에 따르면 Free 플랜의 새 생성물은 Public(CC BY 4.0)이며, Private 선택은 Plus 이상에서 제공합니다. Community에 게시하면 CC0가 되며 게시를 취소해도 유지됩니다. 계정 플랜을 나중에 바꾸어도 생성 시 라이선스가 자동 변경되지는 않습니다.

주인공·룬 문양도 생성 초안과 Blender 후처리를 조합할 수 있습니다. 자산의 용도·원하는 공개 범위와 계정 플랜에 맞는 라이선스를 생성 전에 확인합니다. 각 자산에 생성 당시 선택한 라이선스, 제작자, 원문 자산 URL과 필요한 출처 표기를 기록합니다. 저장소의 공개 여부가 생성 당시 라이선스를 자동 변경하지는 않습니다.

## 첫 아트 검수 구간

전체 임시 자산을 한 번에 교체하기 전에 **리라 1명·수호병 1종·순례자 구역의 전투 공간 1개**를 실제 게임 화면에서 완성도 기준으로 검수합니다. 이 구간은 아직 제작 전이며 완료한 아트로 표시하지 않습니다.

- 리라: 현재 설정의 은회색 머리·흑철/청록/금색 대비를 유지하고 얼굴·손·의상 주름·금속/천 재질을 검수합니다. 큰 단순 도형의 실루엣을 최종 캐릭터로 유지하지 않습니다.
- 움직임: idle·walk·run·dodge·기본 3연격·parry·hit의 9개 기본 클립을 첫 범위로 삼습니다. 공격 궤적·그립·착지·발 접지와 기존 전투 코드의 타이밍을 맞춥니다.
- 환경과 화면: 돌·금속·천의 재질 차이, 접촉 그림자, 키/림 조명, 검 궤적과 피격 VFX, 전투 카메라 거리에서의 가독성을 함께 검수합니다.
- 출력: 같은 원본 자산에서 Windows Forward+ 품질과 웹 Compatibility의 LOD·텍스처·조명 대체를 분리합니다. 두 화면의 실루엣과 재질 인상을 비교하고 실제 성능은 각 플랫폼에서 측정합니다.

정지 화면·근접 얼굴/손·이동·공격 영상과 프레임 시간으로 결과를 확인한 뒤 나머지 적·보스·구역으로 확장합니다. 폴리곤 수 증가나 MCP 연결 완료만으로 AAA급 품질을 합격 처리하지 않습니다.

## 반입 합격 기준

- 단위 1m, 발바닥 y=0. 게임의 이동 전방 -Z와 `SkeletonProfileHumanoid` 리타겟 기준 +Z를 구분합니다. 현재처럼 표현 래퍼에서 방향을 변환하고, 모델과 래퍼에 180도 보정을 중복 적용하지 않습니다. 어깨 높이·손 위치·무기 길이를 실제 공격 판정과 비교합니다.
- 누락 텍스처와 뒤집힌 면이 없고, 걷기·회피·공격에서 관절이 꺾이거나 발이 미끄러지지 않습니다.
- 최종 리그에서는 필수 BoneMap 매핑과 클립 트랙이 모두 해석되고, 이동 클립의 루프와 RESET 포즈를 확인합니다. 체격을 리타겟한 뒤에도 발 접지와 보폭을 다시 측정합니다.
- 공통 PBR 재질을 기본으로 하고 Forward+ 전용 효과에는 웹용 대체 표현을 제공합니다.
- 웹 텍스처는 1~2K, 주요 Windows 자산은 2~4K를 초기 기준으로 합니다. 최종 폴리곤·드로콜 예산은 대표 전투 실측 후 확정합니다.
- GLB의 자동 LOD 설정만으로 성능을 합격 처리하지 않습니다. 서브메시·머티리얼 수, 실제 드로콜과 프레임 시간을 함께 측정하고, 스킨 LOD의 관절·실루엣도 확인합니다.
- 자산별 생성 도구·지시문·원본·수정 이력·사용 조건을 기록하고, 생성 크레딧이 부족하면 Blender 직접 제작으로 계속 진행합니다.
