## 2. 스킬에 추가할 독립적인 제작 판단

다음은 위 사례에서 발전시킨 **자체 응용안**이며 RedefineFX 강의의 정확한 recipe나 보편적인 최적값으로 귀속하지 않는다.

| 응용안 | 제작 절차 | 실제로 확인할 실패 조건 |
| --- | --- | --- |
| 충돌 전후의 표현 상태를 나눈다 | intact/예고, release/이동, confirmed contact, 잔향을 별도 이벤트와 수명으로 정한다. | 빗나감·벽 차단·중단에서도 파손/접촉 burst가 먼저 나타나거나 반복 실행되는가. |
| 영향 범위를 국소화한다 | 실제 접촉점·방향·대상 ID와 effect instance를 연결하고 장식용 force/활성 범위를 제한한다. | 한 대상의 접촉이 무관한 다른 적·주변 오브젝트를 활성화하거나 gameplay 피해를 생성하는가. |
| 큰 형태와 작은 디테일의 표현을 나눈다 | 큰 검기·파편은 읽히는 mesh/저작 움직임으로, 잔여 디테일은 제한된 입자·구운 시퀀스로 후보를 만든다. | 작은 입자를 늘렸는데 주 형태·타격 방향이 여전히 읽히지 않거나 비용만 증가하는가. |
| 변형을 재사용하되 비교는 고정한다 | 작은 변형 집합과 별도 시각용 seed를 정하고 같은 seed/입력의 전후 비교를 남긴다. | 모든 타격이 같은 모양인가, 또는 장식의 RNG 변경이 게임 판정 순서에 영향을 주는가. |
| 힘과 충돌을 다른 역할로 기록한다 | 어느 레이어가 막힘, 흡입/반발, 진행 위치를 소유하는지 명시한다. | collider만 놓고 실제 밀어내기/흡입을 구현했다고 표시하거나 시각 벡터장을 실제 피해/물리로 오해하는가. |
| 자동 저작의 결과를 다시 읽는다 | 실제 도구 발견→작은 자산 변경→readback→반입/컴파일→대표 입력 검수 순으로 범위를 늘린다. | 도구 호출 성공을 정상 asset graph·명중·cook/package·화질 성공으로 대신하는가. |

**중요한 경계:** RFX-D01의 충돌 직전 활성화는 특정 시네마틱 제작 설명이다. 액션 RPG에서 피해·방어 성공·명중 burst를 실제 판정보다 미리 발생시키는 근거가 아니다. preview의 물리 파괴 준비와 권한 있는 gameplay 접촉 이벤트를 분리한다.

## 3. 매개변수 실험과 품질 판정

각 개선안에는 `출처에서 확인한 주장 → 자체 제작 가설 → 고정할 입력 → 바꿀 변수 → 반증 조건 → 실제 근거`를 적는다. 형상·시간·밀도·작은 디테일·환경 반응을 한꺼번에 바꾸지 않는다. 실패한 후보의 source/설정을 남겨 비교의 원인을 보존한다.

검기의 흰 띠 문제라면 **핵심 형상·두께/끝 감쇠 → 밀도/색 분포 → 진행·잔향 → 접촉 반응** 순서의 별도 실험을 제안한다. 이것은 현재 게임 문제에 대한 독립 설계이며 해당 강좌가 대검 검기 해결책을 제공했다는 주장이 아니다.

실제 게임의 정상1배속에서 준비·방출·접촉/빗나감·회수를 보고, 가까움/멀어짐·사선·낮은 품질·밝고 어두운 배경을 비교한다. 원본 렌더와 압축된 전달 영상의 가독성도 나눠 본다. 입자 수·교재 완성 효과 수·도구 호출 수를 AAA 품질 점수로 사용하지 않는다.

## 4. 아직 확인하지 않은 것

로그인 강의실의 실제 노드/설정·전체 영상 시청·자막 분석·새 VFX 제작/베이크·Unreal MCP 연결·실제 Godot/Unreal 실행·목표 기기 성능·최종 AAA는 모두 **pending**이다. 이번 문서가 확인한 것은 공개 기술 글의 범위와 그로부터 구분해 작성한 제작 판단이다.
