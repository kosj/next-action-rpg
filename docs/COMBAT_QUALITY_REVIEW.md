최신 추가 검토: [2026-11-01 공개 영상 프레임 재검토](#2026-11-01-공개-영상-프레임-재검토-v018)는 v0.1.8과 비교한다. 아래 v0.1.7 최초 평가는 당시 기록으로 유지한다.

- [공식 클래스 페이지](https://zeus.com2us.com/gameinfo/class)는 버서커를 대검으로 적 진형을 무너뜨리는 직업으로 설명한다. 페이지에 연결된 공식 클래스 영상은 `https://www.youtube.com/watch?v=9CmiYo06gOQ`이다.
- 같은 페이지의 공개 배경 MP4는 실제 확보해 0/3/6초 프레임을 확인했다. 2878×1280·30fps·7초·오디오 없음이며, 불꽃·불티·안면 강조·대검을 지면 가까이 둔 자세·섬광·파편을 결합한 **홍보 연출**이다. 실제 전투 입력·피격 시간·오디오·지속 성능의 기준으로 사용하지 않는다. 영상·프레임은 프로젝트 자산으로 복사하거나 배포하지 않았다.
- 원본 YouTube 전투 영상은 현재 실행 환경의 접근 제한으로 프레임 검수를 하지 못했다. 버서커의 hitstop 길이·실제 스킬 프레임·음향 품질·현재 라이브 플레이 감각을 직접 측정했다고 주장하지 않는다.
- [10월14일 공식 변경 안내](https://zeus.com2us.com/p/137fc870-5481-44dd-9ca4-205dcaab2f9e)의 HTML 본문에서 버서커 브레이브 슬래시의 발동/사용 시간 단축을 확인했다. 과거 소개 영상으로 현재 라이브의 프레임 수를 추정하지 않는다. 무거운 타격의 목표는 준비·폭발·충돌 후 관성의 대비와 반응성이며, 공격 전체를 느리게 늘이는 것을 합격 조건으로 두지 않는다.

## 이미 갖춘 부분과 혼동하면 안 되는 것

- 실제 리라 runtime은20클립·클립별159채널이다. 약공1/2는53시점, 약공3은71, heavy87, charge66의100Hz bake다. 키가2~3개라서 문제가 생긴다는 설명은 틀리다. 공식을 조밀하게 기록한 것과 개별 동작의 의미 있는 안무는 다르다.
- 현재는 최대80ms 전신 전환 보간이 실제 활성화돼 있다. 과거 보고서의 `No runtime crossfade`를 현재 결함으로 인용하지 않는다. 전환 보간의 존재와 지지발·포즈 속도·상하체 레이어 보존은 별도다.
- 실제 검 Grip/Tip의 world 이력, active 구간의 리본, 게임 공격 시간과 무기 소켓의 같은 프레임 갱신도 있다. “이펙트나 애니메이션 연동이 전혀 없다”는 판정은 틀리다.
- 일반 이동에는 stance 발 궤적 저작이 있다. 그것을 공격의 발디딤·지형 대응·전환 중 접지까지 해결한 것으로 확대하지 않는다.
- 절차 저작·수작업·모캡 중 특정 도구를 AAA의 필수 조건으로 두지 않는다. 결과의 포즈·힘 전달·접촉·타격 반응과 실제 재생 품질을 검수한다.

## 다음 제작 단위와 합격 조건

첫 단위는 **완충 강타 하나로 일반 수호병 한 명을 때리는 장면**이다. 공격·적·카메라·VFX·음향을 함께 완성한 뒤 다른 모션과 적에 확장한다.

1. **강타 동작을 독립 저작:** 지지손·지지발, 골반 선행, 검의 가속, 접촉 후 관성, 회수 자세를 설계한다. 상·하체 차지 표현과 루트 이동을 맞춘다. 무음·VFX off의 고정 카메라에서도 약공/강공/완충이 구분돼야 한다.
2. **피격자가 타격을 설명:** 전용 강피격/필요한 짧은 밀려남을 충돌과 맞춘다. 일반/방패/보스의 저항을 보존하고 명중/빗맞힘/방어/처치 결과를 구분한다.
3. **확정된 접촉 결과에서 연출:** 공격 종류·충전 강도·접촉점/법선·방향·대상 재질·방어/사망 결과를 전달해 hitpause·방향성 카메라·섬광/파편/먼지·음향층을 같은 사건에 맞춘다. 큰 ring이나 피해 숫자만으로 강도를 추측하지 않는다.
4. **실제 입력 기반1배속 AV 비교:** 같은 카메라/거리에서 약공·강공·완충의 명중/빗맞힘/방어/처치12조합을 확인한다. 발·그립·중단·복귀와 적 예고 가독성을 검수하고, 정상속도 영상·소리·목표 기기의 지속 프레임 시간을 함께 승인한다. 헤드리스/소프트웨어1fps를 정상속도·하드웨어 합격으로 사용하지 않는다.

현재 평가서는 수정 방향과 승인 조건을 기록한다. 게임 모션·전투 수치·배포 버전을 변경한 구현 완료 보고가 아니다.

### 장면에서 읽히는 구성

아래 시간은 **편집된 공개 영상의 탐색 구간**이다. 게임 내부의 startup/active/recovery나 hitstop 길이가 아니다.

| 공개본 구간 | 직접 확인한 내용 | 제작에 적용할 원칙 |
| --- | --- | --- |
| 약0–10초 | 근접 시네마틱 컷·강한 블러·검의 밝은 큰 면·원호와 타이틀 전환 | 연출 샷의 강한 인상을 실전 카메라의 조작성과 별도로 평가 |
| 약12–16초 | 전신/얼굴을 보이는 별도 모델 소개, 금속·천·피부와 머리의 시각 구분 | 동작 외에도 얼굴·손·재질을 같은 게임 조명/거리에서 따로 검수 |
| 18.4–20.6초 | 어깨·몸 방향과 검 면이 바뀌고, 흰 칼 궤적 뒤 넓은 붉은 원호가 이어짐. 공격 사이에 상대적으로 효과가 줄어 몸이 다시 보이는 표본도 있음 | 준비 자세·베는 방향·후속 자세의 차이를 전신 실루엣으로 읽히게 구성. 발 고정이나 모든 key의 양손 접촉까지 확인한 것으로 확대하지 않음 |
| 약25–31초 | 생존/버프를 설명하는 문구와 수직 빛·원형 방출·베기 장면이 이어짐.29.3초 부근과29.5초 표본 사이에도 구도 전환이 보임 | 이 전체를 한 번의 지면 강타 준비→접촉→회복으로 합치지 않음. 능력 상태 강조와 실제 칼날 접촉 효과를 구분 |
| 약33–39초 | 대검을 높이 든 상승 전신 실루엣, 넓은 백금색 방출과 먼지, 낮게 무너진 큰 적의 실루엣이 여러 샷에서 보임 | 공격 전후의 높이·면·힘 방향을 크게 대비시키고 적·공간의 반응을 같은 샷에서 확인 |
| 약39–53초 | 수직 방출, 몸 주위 큰 붉은 원호, 넓은 흰/금색 궤적 등 여러 광역 기술이 다른 구도에서 이어짐 | 동작별 효과의 방향과 역할을 정함. 다른 기술의 효과를 한 베기에 모두 더하지 않음 |

33–39초에는 환경과 카메라가 바뀌는 컷이 있다. 원래 떠 있는 적도 있으며 검은 큰 형상 상당수는 날개·수정 돌기가 있는 적 몸체다. 따라서 모든 적의 공중 띄우기나 지형 파괴·파편으로 확정하지 않았다. 35초 still의 주인공은 섬광에 거의 가려져 있어 이 장면으로 손/발·정확한 칼 접촉을 승인할 수 없다. 일부 프레임에는 가장자리 색 번짐·밝기 변화가 보이지만 게임 카메라, 후반 편집, 정확한 흔들림 곡선을 분리 측정하지 않았다.

### v0.1.8과 비교한 다음 제작 우선순위

| 항목 | 현재 확인된 구현 | 다음에 확인·개선할 것 |
| --- | --- | --- |
| 전신의 힘 전달 | 전용 charged_heavy와 차지 상체 레이어, 검/본·명목 지지발 정합 | 큰 준비 실루엣→몸통/검의 방출→관성을 받는 회수로 읽히는지 같은 카메라·효과off·정상1배속에서 검수. 약공3연격의 각 역할과 연결도 별도 안무로 검토 |
| 피격자의 질량 | heavy_hit .48초, 양측75ms 정지와 충돌에 따른 약35cm 이동 | 몸통·골반·다리의 꺾임과 낮아지는 자세, 밀린 뒤 버티고 복귀하는 연기. 적의 종류·방향·벽 조건을 유지하며 단순 평행 이동으로 보이는지 검사 |
| 바닥·공간 반응 | 확정 hurtbox 접촉의 sparks/debris와 제한된 카메라/오디오 전달 | 현재 대각베기의 역할에 맞는 표면·바닥 반응을 설계. 실제 무기/지면 접촉 여부와 가림을 확인해 발생시키며 근거 없는 지면 폭발이나 참조 게임의 전체 광역 효과를 덧붙이지 않음 |
| 강조의 절제 | active 구간의 검 잔상, 확정 접촉당 시작하는 camera kick/FOV·impact VFX·접촉 음향 | 준비의 대비→짧은 최고점→적 예고를 다시 볼 수 있는 회복을 함께 검수. 소리의 청취와 동일1배속 영상 동기는 별도 승인 |

다음 대표 단위도 **기존 완충 강타 하나와 일반 수호병의 반응**을 중심으로 한다. 같은 거리·카메라에서 명중/빗맞힘/방어/처치를 촬영하고, 효과를 끈 몸 동작과 효과/음향을 켠 접촉을 나눠 비교한다. 벽·회전·중단에서 발과 검이 흔들리는지도 포함한다. 기능 통과 수, 효과의 개수, 높은 bake 빈도나 참고 영상의 인지도로 AAA 달성률을 만들지 않는다. 이번 기록은 분석과 다음 작업 근거이며 게임 코드나 배포판을 변경하지 않았다.
