# 대표 구간 AAA 아트 승인 기준

기준일: **2026-10-31**. 사용자 목표는 스텔라 블레이드에 견줄 수 있는 실사 지향 액션 RPG의 아트 품질입니다. 첫 승인 단위는 **리라·룬검, 일반 근접 수호병·검, 첫 순례자 전투 공간**입니다. 현재 생성 캐릭터·프로젝트 저작 스켈레톤 모션·환경 재질·장면 개선은 검토 가능한 제작 단계이며, **최종 AAA 아트 승인은 `pending`**입니다.

[대표 구간 제작 계약](ART_SLICE.md), [제작 입력 명세](../art_source/production/asset_specs.json), [모션 계약](../art_source/production/motion_contract.json), [캐릭터 반입 기록](CHARACTER_INTEGRATION.md)을 함께 사용합니다. 삼각형 수, 텍스처 해상도, 생성 성공, 본·클립 개수와 자동 검사 통과는 각각의 제작·구조·성능 자료입니다. 이 수치에 도달했다는 이유로 시각 품질을 승인하지 않습니다. 검사 범위는 당시 파일 해시와 함께 보존하며 과거 결과를 새 파일의 결과로 바꾸지 않습니다.

## 화면과 증거를 고정하는 방법

검수마다 커밋, runtime GLB·재질·텍스처 해시, 엔진·렌더 경로, 플랫폼, 해상도, 품질 모드, 카메라와 조명 조건을 기록합니다. 캡처는 실제 게임의 자산·표현·전투 시간을 사용합니다. 중립 스튜디오 렌더는 형태·표면 확인에, 콘셉트는 의도 비교에 사용하고 실제 게임 화면과 구분합니다.

같은 판본으로 아래 샷과 영상을 확보합니다. 변경 전후 비교에는 같은 카메라·노출·포즈를 사용하며, 정지 그림과 1배속 동영상을 함께 봅니다.

| 증거 | 필수 내용 |
| --- | --- |
| 리라·수호병 전신 | 정면·측면·후면 REST, idle와 대표 전투 포즈. 비례·실루엣·발바닥·장비 크기를 함께 확인 |
| 리라 얼굴·양손 근접 | 정면·사선 얼굴, 손등·손바닥·그립. 실제 게임의 중립광과 첫 방 조명에서 확인 |
| 수호병 머리·양손 근접 | 투구·목·눈 주변, 손가락·가드·칼자루 접촉. 공격·방어 중 큰 장식과 몸체 간섭 확인 |
| 실제 플레이 카메라 | 첫 방 입구→적 접근→교전→출구. 플레이어·적·위험 예고·진행 방향과 카메라 가림 확인 |
| 모션 전체와 전환 | 각 클립의 전체 동작, 방향 이동, 3연격·중공격·차지·스킬·회피·패링·피격·사망·복귀와 가능한 취소/교차 전환 |
| 재질·품질 비교 | 동일 장면·동작의 Web Compatibility 품질 0/1과 Windows 실제 렌더 설정. 근접·플레이 거리·비스듬한 바닥 시점 |

## 모델·얼굴·손·변형

리라의 [콘셉트](../art_source/production/references/lyra-front-concept.png)와 수호병의 [콘셉트](../art_source/production/references/sentinel-front-concept.png)를 비례·의상·표면 구분의 기준으로 사용합니다. 얼굴은 눈·눈꺼풀·입술·콧방울·턱의 형태, 시선과 좌우 일관성, 피부·눈·치아·머리카락의 분리를 근접에서 확인합니다. 뭉개진 생성 형상, 그려진 눈의 착시, 늘어난 UV나 광택으로 결함을 숨긴 표면을 수정합니다. 표정이나 시선 기능을 사용하는 장면은 그 변형도 포함합니다.

양손은 손가락의 분리·관절 굽힘·엄지 위치·손바닥 두께와 손목을 확인합니다. 무기를 쥔 모든 주요 포즈에서 손가락이 자루를 감싸고 손바닥과 그립이 접촉해야 합니다. 떠 있는 손, 가드·날 관통, 손목 꺾임과 프레임 간 그립 미끄러짐은 해결할 결함으로 남깁니다. 휴리스틱 소켓 좌표가 정상이라는 사실만으로 접촉을 승인하지 않습니다.

각 클립의 모든 저작 key timestamp와 출력 프레임 간격의 중간 포즈를 평가합니다. 최대 관절 회전·보폭·무기 속도 시점도 포함하고, 실제 렌더를 1배속·느린 재생·근접 정지로 검토합니다. 어깨·겨드랑이·팔꿈치·손목·골반·무릎·발목의 체적, 뒤집힌 면·틈·급격한 스킨 신장, 갑옷·몸·의상의 관통을 기록합니다. [변형 검토 도구](../tools/review_character_deformation.py)의 수치·키 표본과 시각 판정은 각각 보관합니다. REST나 시작·중간·끝 세 포즈의 통과로 전체 변형을 승인하지 않습니다.

## 움직임·접촉·머리카락·의상

대기↔이동↔달리기, 전후·측면 이동과 방향 전환, 착수·감속, 공격의 준비→타격→회복, 회피·패링·피격·사망·복귀를 실제 입력으로 검토합니다. 전환 중 포즈 튐, 몸·무기 순간이동, 보간 중 손 접촉 이탈, 취소된 동작의 지연 이벤트가 없어야 합니다. 차지 hold와 이동 중 heal/charge의 현재 표현 정책은 [반입 기록](CHARACTER_INTEGRATION.md)에 따라 명시하며, 승인에 필요한 표현 범위를 그 정책과 대조합니다.

발은 체중이 실리는 구간에 지면과 접촉하고, 코드 이동 속도에 맞는 보폭·몸 중심·회전과 공격 발디딤을 가져야 합니다. 발 끌림·뜸·지면 관통·런지 중 미끄러짐과 회피 후 급정지를 영상에서 확인합니다. 저작 단계의 선택 sole vertex 수치는 검수 근거의 일부입니다. 동적 이동·경사·교차 전환·실제 접촉의 확인을 따로 남깁니다. 공격 궤적·무기 길이·적중 순간·피격 반응·트레일은 실제 판정 시간과 맞아야 하며 접촉 인상을 꾸미려고 검이나 판정만 임의 확대하지 않습니다.

머리카락·의상은 의도한 재질과 실루엣을 유지하고 머리·어깨·다리·무기와의 간섭을 해결합니다. 큰 고체 덩어리처럼 붙은 머리, 두피 틈·알파 정렬 오류·빛 번짐, 급회전에서 튀는 천과 갑옷은 근접·플레이 거리에서 확인합니다. 본·저작 보조 모션·물리 중 선택한 표현 방식과 충돌 범위를 기록하고, 정지·질주·회피·피격·복귀에서 연속성을 검토합니다. 물리 기능의 유무 자체를 품질 판정으로 사용하지 않습니다.

## 표면·환경·조명·VFX

피부·머리·천·가죽·흑철·청록·금색 장식·석재는 색뿐 아니라 거칠기·법선·반사 응답으로 구분합니다. 하나의 atlas를 쓰더라도 근접과 움직이는 빛에서 표면 구분이 유지되어야 합니다. 반복 크기, texel 밀도 변화, UV 이음새·늘어짐, 계단 현상·반짝임, 거리별 밉맵과 LOD 전환을 확인합니다. albedo는 sRGB, normal과 ARM/ORM은 linear, 노멀은 OpenGL +Y이며 packed map의 채널을 검증합니다. 방향성 그림자와 조명을 albedo에 중복 굽지 않습니다.

[첫 방 목표 그림](../art_source/production/references/sanctuary-courtyard-target.png)을 실제 조립 구도와 비교합니다. 첫 방은 입구·교전 중심·출구가 읽히고, 기둥·잔해·흙·마모가 크기와 사용 흔적에 맞아야 합니다. 중앙 교전 공간·잠금 문·충돌·카메라를 보존하며 큰 바닥의 반복과 주변 잔해의 배치 규칙이 눈에 띄는지 확인합니다. 균일한 회색 블록아웃을 최종 환경으로 승인하지 않습니다.

중립광에서 표면을 확인한 뒤 실제 방에서 키·필·환경 반사·노출·그림자·안개를 조정합니다. 밝은 돌과 금속이 날아가거나 청록 안개·강한 색광으로 캐릭터와 지면이 뭉개지는지 확인합니다. 광원 방향과 접촉 그림자·가림은 일관되어야 합니다. UI를 켠 실제 전투에서도 적의 준비 동작과 공격 예고, 패링/피격 성공, 무기 궤적이 읽혀야 합니다. VFX의 밝기·지속·잔상·카메라 반응은 타격을 설명하고, 적과 지면·출구를 지속적으로 가리는 효과는 수정합니다.

새 [courtyard 재질 기록](../art_source/production/courtyard_materials/README.md)은 출처·물리 크기·채널과 중립 렌더의 근거입니다. 해당 재질의 독립 반입 통과는 통합 장면의 조명·구도·재질 승인과 분리합니다.

## Web·Windows 품질과 실제 성능

공유 원본에서 Web의 LOD·해상도·주변 소품 밀도·그림자·지원 조명을 조정하되 주인공과 수호병의 실루엣·얼굴·손·그립·대표 재질 구분·공격 가독성을 보존합니다. 같은 구도·동작의 품질 0/1과 Windows 화면을 대조하고, 품질 전환에서 블록아웃·누락 장비·불안정한 표면으로 바뀌는지 확인합니다. Web 테스트 경로가 빠르다는 이유로 최종 아트 요구를 낮추지 않습니다.

먼저 목표 GPU·CPU·메모리·OS·드라이버·브라우저와 Windows 렌더 경로를 고정합니다. [기존 계약](ART_SLICE.md)의 Windows 1080p·Web 720p, 60fps/약 16.7ms는 **목표**입니다. 정지 idle, 대표 교전, 다수 VFX·그림자가 겹치는 구간을 일정한 입력으로 측정하고 평균·p95·p99 프레임 시간, CPU/GPU 시간, 드로콜·메모리·첫 로딩·셰이더 준비와 반복 로딩을 기록합니다. 지속적인 프레임 예산 초과나 이동·공격 중 hitch는 승인 전에 원인·대응과 재측정 결과를 남깁니다.

소프트웨어 WebGL·headless 테스트·자동 LOD 설정·정적 삼각형 계수는 목표 GPU 성능의 측정값으로 사용하지 않습니다. 원본 JPEG bytes, Godot의 밉맵 포함 import bytes, 전체 PCK·Web 전송량, 상주 메모리는 따로 측정합니다. 새 courtyard는 원본 **9,785,368 bytes**, 독립 Godot 4.7.2 lossless+mip `.ctex` **21,504,226 bytes**를 확인했습니다. 최종 통합 빌드의 전체 용량·메모리·프레임은 해당 빌드로 다시 확인합니다.
