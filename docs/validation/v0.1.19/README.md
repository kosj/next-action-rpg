## 시험 후 기각한 후보

- **블룸(Glow)**: 같은 고정 카메라의 [채택 화면](media/scene-q0.png)과 [Glow 후보](media/scene-glow-rejected-q0.png)를 비교했다. Glow를 켜면 바닥 평균 RGB가 약 (142.8, 113.5, 88.5)→(146.0, 121.9, 100.2), 표준편차가 약 (21.9, 18.4, 20.8)→(17.2, 16.0, 19.7)로 바뀌어 화면 전체 대비가 낮아졌다. 사실상 발광하지 않는 HDR 임계 4.0·강도 0.1에서도 같은 변화가 나서 블룸 수치 조정으로는 해결되지 않는다. Glow는 끄고 회귀 검사로 고정했다. 실제 GPU/브라우저에서의 원인은 확인하지 않았다.
- **`GeometryInstance3D.transparency` 디졸브**: 실제 렌더에서 dissolve 1.0·transparency 1.0인 적이 3초 제거 직전까지 불투명하게 남았다. 개체별 재질 사본의 alpha-hash 디더링으로 바꿨고 공유 원본 재질 보존을 native 검사로 확인한다.
- **첫 저체력 비네트**: 체력 12%에서도 가장자리 알파가 약 0.16이어서 화면에서 거의 보이지 않아 세기를 올렸다.
- **사각형 불씨**: 텍스처 없는 사각 빌보드가 픽셀 조각처럼 보여 둥근 가산 셰이더로 바꿨다.

### Web 용량 예산과 스크립트 압축

첫 PR 커밋(fe8380b)의 CI는 965/0 회귀를 통과했지만 `audit_runtime_package.py`가 원시 Web 150,029,043 B로 상한을 **29,043 B 넘어** 실패했다. 로컬에서 쓴 `build.py`의 내장 검사는 라이선스 파일을 더하기 전에 재므로(149,917,761 B) 통과했다. 기준 커밋과 PCK 항목을 비교하니 증가분은 새 스크립트·셰이더 75,559 B와 기존 스크립트 증가였고, 바이너리 토큰 `.gdc`가 원본 텍스트보다 커서(예: `actor_feedback.gdc` 35,644 B) 비중이 컸다.

Web 프리셋만 `script_export_mode=1`(바이너리 토큰)→`2`(압축 바이너리 토큰)로 바꿨다. PCK의 `.gdc` 합이 1,068,952 B→317,555 B(−751,397 B)로 줄어 원시 Web이 149,277,699 B가 됐다. 같은 내보내기로 데스크톱·모바일 브라우저 검사를 다시 통과했고, 이 수정과 import 부산물 되돌림을 포함한 커밋 5e63329의 CI [run 45357814841](https://github.com/kosj/next-action-rpg/actions/runs/45357814841)에서 build(회귀·예산 감사·WebGL 저장 검사), 차지 강타 검사, 모바일 내보내기 검사가 모두 통과했다. Windows 프리셋은 실행 검증 수단이 없어 그대로 두었다.

native 첫 실행의 실패(타입 추론 파싱 오류, 원점에서 먼 float32 위치의 엄격한 비교, headless 더미 렌더러의 스킨 굽기·재질 사본 엔진 오류)는 원인을 고쳐 다시 실행했다. 더미 렌더러에서는 잔상 몸체 굽기와 재질 사본 할당을 건너뛰며, 실제 렌더에서 두 경로가 동작함을 위 화면으로 확인했다.

## 남은 검증

main 병합 뒤의 Pages·릴리스와 공개 주소 검사, 정상 입력 플레이 영상, 연속 시청/청취, 실제 Android/iOS/Windows GPU에서의 화면 그레이드·잔상 굽기 비용, AAA 아트 승인은 확인하지 않았다. 표의 로컬 수치는 커밋 전 작업 트리에서 얻었고, PR 커밋의 CI 결과는 위 예산 절에 따로 적었다.
